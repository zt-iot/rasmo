### NOTE:
The Login Filter requires `CAP_NET_ADMIN` capability:

	# e: active at exec, p: permitted to raise
	sudo setcap cap_net_admin+ep ./login_filter

or through systemd service:

	[Service]
	AmbientCapabilities=CAP_NET_ADMIN
	CapabilityBoundingSet=CAP_NET_ADMIN

## Usage

### RASMO On-device Topic Hierachy

`local/audit/syscall`: Linux Audit `AUDIT_SYSCALL` records

`local/audit/login/{success,failed}`: Linux Audit `USER_AUTH` records

`global/cpsp/report/syscall`: syscall anomalies emitted by supervisors or the syscall filter

`global/cpsp/report/login`: IP blocking policies reported by the login filter

`global/cpsp/sync/#`: synchronization batch published by the security controller

`global/cpsp/sync-ack/#`: sync acknowledgement published by the login filter

### profiling an application (experimental)

1. Write strace script (e.g., profile_libcamera.sh)
2. execute profiler:

```sh
./seccomp_create -i <script_path> -o <profile_output_path>
```

For example, libcamera:

```sh
./seccomp_create -i script/seccomp/profile_libcamera.sh -o output/rpicam-vid
```

### Supervisor

Execute the command:

```sh
	./seccomp_load -i <profile_path> -- <app_path> <app_args>
```

For example, video streamer:

```sh
./seccomp_load -i output/rpicam-vid -- rpicam-vid --width 640 --height 480 \
	--framerate=60 --inline -n -t 0 -o - |\
./seccomp_load -i output/gst_camera/ -- gst_camera localhost
```

#### Emitted Linux Audit example record for seccomp filter violation

`AUDIT_SECCOMP` example:

```text
type=SECCOMP msg=audit(1784688858.098:32848467): auid=1000 uid=1000 gid=1000 ses=16331 pid=405575 comm="gst_camera"
	exe="/usr/local/bin/gst_camera" sig=0 arch=c00000b7 syscall=64 compat=0 ip=0x7f89b9ac24 code=0x50000 ...
	ARCH=aarch64 SYSCALL=unknown-syscall(-1)
```

### Linux Audit Plugin

Write plugin configuration file under `audit/plugins.d/` (e.g., `/usr/local/etc/audit/plugins.d`).
A simple example:

```text
active = yes
direction = out
path = /path/to/the/monitor_plugin
type = always
args = pass=0,needed=1,arguments=2
format = string
```

#### Load Linux Audit Rules

```sh
# clean all the previoius rules
sudo auditctl -D

# load rules generated by the profiler
# NOTE: the audit.rules file must be owned by root and not readable by other users;
# otherwise it will be rejected
sudo auditctl -R output/audit.rules
```

## Security Controller (Zabbix Server)

For python action scripts:

```sh
apt install python3-psycopg2
```

Install unixODBC and PostgreSQL unixODBC database driver for database monitoring:

```sh
apt install unixodbc unixodbc-dev odbc-postgresql
```

### Configure unixODBC

```sh
obdcinst -j
```

Edit odbc.ini and odbcinst.ini

### Configure Zabbix

* Get Zabbix default home

```sh
getent passwd zabbix	# by default /var/lib/zabbix
```

Put `.pgpass` file in Zabbix home directory remember to `chown` and `chmod 600`.

* create blocklist.conf to store token for accessing Zabbix APIs
* Zabbix alert scripts should be put at AlertScriptsPath (check `zabbix_server.conf`)
* Systemd service file: `/usr/lib/systemd/system/zabbix-agent.service`

#### Setup PSK to encrypt communication

Check [Using pre-shared keys](https://www.zabbix.com/documentation/current/en/manual/encryption/using_pre_shared_keys) for 
configuration details.

* Required to set up PSK in `zabbix_agentd.conf` on each host, including the self-monitoring host on the Zabbix server.
* Useful logs can be found in `/var/log/zabbix/`
* Dispatcher is based on `ssl` module  with TLS 1.2 
* Zabbix Agent and Zabbix server messages are encrypted by TLS 1.3


#### NOTE:
* Zabbix keeps using the value cache to calculate triggers even if you clear the history of the item.
  In my case `max()` funciton keeps on using the old values even if I reset the history of sync.cursor. 
  To solve it, restart the zabbix server.
* `max(sync.cursor, 31d)` will report not enough data if the item is empty, therefore each device needs to initialize its history by sending a `INIT` message.

#### How to Change Affinity of user.slice and system.slice

```sh
systemctl set-property init.scope AllowedCPUs=3
systemctl set-property system.slice AllowedCPUs=3
systemctl set-property user.slice AllowedCPUs=3
```

`system.control/xxx.conf` are auto generated to manage these two slices based
on the properties provided in the commandline.

monitoring.slice affinity:
`/etc/systemd/system/monitoring.slice.d/monitoring.conf`
Scheduling method is set in each service file.

Added `detect_enforce.slice` for the filter and applications.
Config file: `detect_enforce.slice.d/detect_enforce.conf`
